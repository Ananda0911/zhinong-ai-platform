五、测试过程中的"假警报"与排查实录

本轮出现 3 起 UI 层异常报告，经逐一深挖全部证实为测试环境干扰，产品无缺陷 —— 排查过程本身构成报告的一部分

异常现象初步怀疑排查与真相
buyertest 发布求购 403（两轮"稳定复现"） 前端 PublishView 接口选择逻辑 bug API 直连 8000 → 201；经 vite 代理 5173 → 201；单 agent 串行浏览器实测 → 201。真相：并行测试 agent 共享同一浏览器实例，登录态互相覆盖（farmer 的 token 发给了 buyer 接口）→ 403
农技对话采样长度 6 秒恒定不变 流式渲染又坏了 同因：并发 agent 导航/登录把页面切走。串行验证回答正常渲染（1623 字），流式渐进多轮独立确认
admin 访问 /admin/policy-docs 被重定向 路由守卫 bug 同因：登录态被覆盖成非 admin，守卫正确拦截。串行验证正常进入，文档列表 3 个 ready
测试方法学结论（已固化到流程）：多角色 UI 验收必须串行执行——并行 agent 共享浏览器会导致登录态互相覆盖，制造"角色错乱"型假故障（403 / 重定向 / 页面互切）。本轮所有并行阶段的异常报告经串行复核后全部推翻。
