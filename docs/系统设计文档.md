## 1. 项目概述

### 1.1 背景与目标

面向农业生产与流通环节的 AI 服务平台，用大模型能力解决三农场景三类问题：

- **种不好**：缺乏及时、专业的农技指导（病虫害诊断、种植养殖咨询）
- **卖不掉**：供需信息不对称，农产品滞销
- **卖不好**：农产品电商化程度低，缺营销内容生产能力

项目定位：**学习练手为主、可真实落地**。AI 编排采用 LangGraph（LangChain 官方主推的编排框架），模型全部走云端通义 API，本地零运维。

### 1.2 用户角色

| 角色 | 代码 | 使用端 | 核心诉求 |
|---|---|---|---|
| 供应方（农户/合作社工作人员） | `farmer` | PC Web | 农技咨询、病虫害诊断、发布供应、生成营销文案 |
| 采购方（采购商/批发商） | `buyer` | PC Web | 发布求购、浏览货源、获取匹配推荐 |
| 平台管理员 | `admin` | PC Web | 用户管理、政策知识库维护、内容治理、数据统计 |

> 说明：MVP 阶段农户个人由合作社工作人员代操作（PC 端），二期做小程序让农户直接使用。

### 1.3 MVP 范围（已确认）

| 模块 | 功能 | AI 能力 | 定位 |
|---|---|---|---|
| 农技 AI 助手 | 种植养殖问答 + 病虫害拍照识别 | qwen-plus / qwen-vl-plus | 核心亮点 |
| 产销对接 | 供应/求购信息发布 + AI 智能匹配 | text-embedding-v3 向量匹配 | 助农核心价值 |
| 营销工具 | 商品文案 / 直播话术 / 短视频脚本生成 | qwen-plus 文本生成 | 低成本陪衬 |
| 政策问答 | 惠农政策知识库问答（RAG） | qwen-plus + text-embedding-v3 | RAG 场景 |

**明确暂缓**（二期以后）：价格行情预测（无真实数据积累，冷启动无法做）、政府数据大屏、小程序端。

## 3. AI 能力设计（通义千问）

### 3.1 模型选型

| 场景 | 模型 | 理由 |
|---|---|---|
| 农技问答 / 营销文案 / 政策问答生成 | `qwen-plus` | 效果与成本均衡，支持长上下文 |
| 病虫害图片识别 | `qwen-vl-plus`（默认）/ `qwen-vl-max`（可配置升级） | vl-plus 性价比高，识别效果已够用 |
| 向量化（RAG 检索、产销匹配） | `text-embedding-v3` | 1024 维，中文效果好 |

全部走 **DashScope OpenAI 兼容模式**，经 `langchain-openai` 接入（换供应商只改 base_url 和模型名）。

### 3.2 统一 LLM 封装（services/llm.py 核心）

```python
from langchain_openai import ChatOpenAI
from app.config import settings

# 通义千问 DashScope OpenAI 兼容模式，经 langchain-openai 接入
llm = ChatOpenAI(
    api_key=settings.DASHSCOPE_API_KEY,
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
    model=settings.MODEL_TEXT,   # 默认 qwen-plus
    streaming=True,
)

async def chat_stream(messages: list):
    """流式对话（LangGraph 节点内通用），逐 token yield 文本增量"""
    async for evt in llm.astream_events(messages, version="v2"):
        if evt["event"] == "on_chat_model_stream":
            content = evt["data"]["chunk"].content
            if content:
                yield content
```

> 设计要点：
> - 模型名不硬编码在业务代码里，集中在 `config.py` 配置（`MODEL_TEXT` / `MODEL_VL`），便于切换模型或供应商；
> - 业务流程（问答 / 诊断 / RAG / 文案）一律在 `services/graphs/` 下用 LangGraph 组织，路由层只做参数校验与 SSE 转发。

### 3.3 Prompt 设计

**① 农技问答（system prompt）**

```text
你是一位经验丰富的农业技术专家，为农户和合作社工作人员提供种植、养殖技术指导。

要求：
1. 回答实用、具体、可操作，分点说明关键步骤；
2. 用通俗易懂的语言，避免不必要的专业术语，出现术语时用一句话解释；
3. 涉及用药时，必须提醒安全间隔期和用量限制；
4. 信息不足时先追问关键细节（如作物品种、生长阶段、地区），再给建议；
5. 不确定时明确说明，不编造；遇到超出农业范围的问题，礼貌拒绝。
```

**② 病虫害识别（图片消息的 system prompt）**

```text
你是农作物病虫害诊断专家。用户会上传作物照片（可能附文字说明）。
请按以下结构输出诊断结果：

【诊断结论】判断是病害/虫害/生理性问题时，给出最可能的 1-2 个具体名称及置信程度
【症状依据】照片中观察到的关键症状
【成因分析】可能的诱因（气候、土壤、管理等）
【防治方案】分"农业防治""化学/生物防治"两部分，具体到药剂名称与浓度
【用药提示】安全间隔期、轮换用药等注意事项
【严重程度】轻度/中度/重度，及是否建议求助当地农技部门

若照片与作物病虫害无关，说明无法诊断并引导用户重新拍摄。
```

**③ 营销文案（按 gen_type 切换 user prompt 模板）**

```text
你是农产品电商营销专家。根据以下产品信息，生成{类型}：

产品名称：{product_name}
类目：{category}
特点：{features}
卖点：{selling_points}
风格要求：{tone，如"接地气/突出产地故事/强调绿色健康"}

类型要求：
- detail（商品详情页文案）：吸引人的标题 + 3-5 个卖点短句 + 分段详情介绍 + 建议标签
- live（直播话术）：开场引流 → 产品介绍 → 促单话术 → 互动答疑预设（4 段）
- video（短视频脚本）：分镜头脚本，含画面描述 + 口播文案，总时长约 60 秒
```

**④ 政策问答（RAG，system prompt）**

```text
你是惠农政策咨询助手，只依据提供的政策资料回答问题。

规则：
1. 只使用【政策资料】中的内容回答，可适度组织语言但不得添加资料外的信息；
2. 回答末尾注明依据的政策文档名称；
3. 资料中没有相关内容时，明确回答"当前知识库暂无此政策信息"，不编造；
4. 涉及补贴金额、申请条件、截止日期等关键数字时，原样引用资料原文。

【政策资料】
{retrieved_chunks}
```

### 3.4 轻量 RAG 链路（政策问答，LangGraph 编排）

使用 LangChain 生态组件组装，检索器自实现（量小无需外部向量库）：

```
入库：上传文档 → MinerU 解析为 Markdown → Splitter 分块 → 向量化入库（后台任务）
问答：提问 → Retriever 检索 Top-5 → 拼装 Prompt → 流式生成
```

| 步骤 | 实现 |
|---|---|
| 文档解析 | **MinerU 2.x**：PDF/扫描件 → Markdown（保留表格结构、版面阅读顺序、OCR）；docx/txt 直接读取 |
| 分块 | `RecursiveCharacterTextSplitter`（chunk_size=500，overlap=50） |
| 向量化 | `OpenAIEmbeddings`（text-embedding-v3，指向 DashScope 兼容端点），序列化为 BLOB 存 `policy_chunks` 表 |
| 检索 | 自实现 `BaseRetriever`：问题向量化 → **全量加载 chunk 向量到内存** → 余弦相似度 Top-5 |
| 编排 | LangGraph 两节点图 `retrieve → generate`，generate 节点流式输出 |

> 为什么检索器自实现而不接 FAISS/Chroma：政策文档量级为几十份、数千 chunk，SQLite BLOB + NumPy 全量内存检索耗时 <10ms，零外部依赖。实现为 `BaseRetriever` 后对 LangGraph 完全透明，将来量级上来可直接换成 sqlite-vec / Milvus 的 VectorStore，业务代码不动。

**回答流程**：LangGraph `retrieve` 节点取 Top-5 → 拼入 `【政策资料】` → `generate` 节点 qwen-plus 流式生成 → FastAPI 转发 SSE 逐字显示。

**MinerU 接入说明**：

- 部署模式可配置（`config.py` 的 `MINERU_MODE`）：`local`（默认，pip 安装、模型自动下载，2.1B VLM，CPU 可跑 GPU 更快，免费）或 `api`（MinerU 官方托管 API，按页计费，本地零资源占用）
- 解析耗时较长（本地 CPU 每页数秒），走 **FastAPI BackgroundTasks 后台任务**：上传接口立即返回 `processing`，解析 + 分块 + 向量化完成后置 `ready` / `failed`，前端轮询文档状态
- MinerU 输出的表格为 HTML 形式，直接 embedding 效果差：**分块前将表格线性化**为"字段：值"的纯文本（如"补贴标准：每亩 150 元"）
- docx/txt 版式简单，跳过 MinerU 直接读取，节省解析时间

### 3.5 产销智能匹配

**方案**：语义向量相似度 + 硬规则过滤。

```
发布时：拼接文本（品类+品种+数量+产地+描述）→ embedding → 存入本表 embedding 字段
匹配时：
  1. 硬规则过滤：品类一致、对方状态为 active、未过期
  2. 计算供需双方 embedding 余弦相似度，取 Top-5
  3. 返回列表：匹配条目 + 相似度分数（映射为 高/中/低 标签）
```

> 好处：无冷启动问题、可解释（"为什么推荐"由大模型基于双方文本生成一句话理由，可选做）。匹配在发布时预计算向量，查询时只做内存计算，响应快。

## 4. 功能模块设计

### 4.1 农技 AI 助手

**功能点**

- 多轮对话（流式输出），支持追问
- 图片上传 → 病虫害结构化诊断
- 会话管理：历史会话列表、自动标题（首条消息前 20 字）、删除会话

**交互流程**

1. 用户进入助手页 → 左侧会话列表，右侧对话区
2. 发送文字问题 → SSE 流式返回
3. 上传图片（前端 canvas 压缩至 1MB 内）→ 先调 `/api/upload/image` 拿 URL → 发送带图消息 → 后端读图转 base64 传 qwen-vl → 流式返回结构化诊断
4. 对话历史保留最近 10 轮作为上下文，超长截断

### 4.2 产销对接

**功能点**

- 供应信息：发布（标题/品类/品种/数量/价格或面议/产地/描述/图片≤6张）、编辑、下架
- 求购信息：发布（标题/品类/数量/意向产区/预算/描述）、编辑、关闭
- 列表页：按品类/地区/关键词筛选，分页
- 详情页：基本信息 + **AI 匹配推荐**（为该供应推荐求购 / 为该求购推荐供应，Top-5 带相似度标签）
- 状态流转：`active`（在售/求购中）→ `offline`（手动下架）/ `expired`（过期自动失效，按 expire_at）

**交互流程（匹配）**

1. 采购商打开某条求购详情 → 右侧栏展示"AI 为您匹配的货源 Top-5"
2. 每条显示：供应标题、产地、数量、价格、匹配度标签（高 ≥0.75 / 中 0.5-0.75 / 低 <0.5）
3. 点击可跳转供应详情，联系方式需登录可见

### 4.3 营销工具

**功能点**

- 表单输入：产品名称、类目、特点（多选/自填）、卖点、风格
- 三种生成类型：商品详情页文案 / 直播话术 / 短视频脚本
- 结果区：流式生成、一键复制、重新生成
- 生成历史（本人最近 20 条）

### 4.4 政策问答

**功能点**

- 用户侧：对话式问答，流式输出，回答附政策文档出处
- 管理侧：上传 docx/pdf/txt 政策文档 → MinerU 后台解析 → 分块向量化入库 → 状态显示（处理中/就绪/失败，前端轮询）、删除文档（级联删 chunk）

### 4.5 管理后台

- 用户管理：查询、启用/禁用
- 内容治理：供应/求购全量列表，强制下架违规内容
- 政策文档管理（见 4.4）
- 工作台统计：用户数、供应/求购数、AI 问答次数、文案生成次数

## 6. API 设计

### 6.1 通用约定

- 前缀 `/api`，JSON 交互；对话生成类接口为 **SSE 流式**（`text/event-stream`）
- 认证：`Authorization: Bearer <JWT>`（登录/注册除外）
- 错误格式：`{"code": 40001, "message": "参数错误"}`（FastAPI 异常处理器统一封装）
- 分页参数：`?page=1&size=10`，响应 `{list, total, page, size}`
- 权限标注：`公开` / `登录` / `farmer` / `buyer` / `admin`

### 6.3 SSE 约定

```
event: message   data: {"delta": "防治方案……"}     ← 文本增量
event: message   data: {"delta": "……"}
event: done      data: {"message_id": 123}          ← 结束，返回落库消息 id
event: error     data: {"message": "生成失败，请重试"} ← 异常
```

> 前端用 `fetch` + `ReadableStream` 解析（Axios 不支持流式读取响应体），封装成 `utils/sse.js`。

## 8. 实施计划（按阶段，验收驱动）

### Phase 1 · 项目骨架
- 前后端项目初始化、目录搭建、跨域与代理配置（Vite dev proxy → 8000）
- JWT 认证全链路（注册/登录/me），角色路由守卫
- `llm.py`（ChatOpenAI 封装）+ LangGraph 冒烟脚本 + .env 配置
- **验收**：能注册登录，三种角色看到不同菜单；通义 API 调通

### Phase 2 · 农技 AI 助手
- 会话/消息表与接口、SSE 流式对话、上下文管理（保留 10 轮）
- 图片上传 + qwen-vl 病虫害结构化诊断
- **验收**：问答流式输出；上传作物照片返回结构化诊断

### Phase 3 · 产销对接
- 供应/求购 CRUD、列表筛选分页、图片上传
- embedding 预计算 + 匹配接口 + 详情页匹配侧栏
- **验收**：发布供应后，为求购详情能看到匹配的货源及相似度

### Phase 4 · 营销工具 + 政策问答
- 文案生成三模板 + 生成历史
- 政策文档上传 → MinerU 后台解析 → 分块入库 → RAG 问答（附出处）
- **验收**：三种文案可生成复制；上传政策文档后问答能引用出处，无依据时明确拒答

### Phase 5 · 管理后台与打磨
- 用户管理、内容治理、文档管理、工作台统计
- 过期状态自动失效（查询时惰性判断即可，无需定时任务）
- 整体联调、角色权限全量测试
- **验收**：管理员可禁用用户/下架内容/维护政策库；全流程角色走通

## 9. 风险与注意事项

| 事项 | 处理方案 |
|---|---|
| API Key 安全 | 只存 `.env`（git ignore），提供 `.env.example` |
| 费用控制 | 默认 qwen-plus / qwen-vl-plus（非 max 档）；单条消息上下文截断至 10 轮；图片前端压缩 |
| SSE 开发坑 | Vite 代理需关闭缓冲（`proxy 配置 headers` / `compress: false`）；Nginx 部署时 `proxy_buffering off` |
| 内容安全 | 通义 API 自带内容安全审核；发布类内容由管理员兜底下架 |
| SQLite 并发 | FastAPI 单进程 + 短事务足够；Session per request，写操作即用即提交 |
| 图片存储 | 限制 ≤2MB、jpg/png/webp；按日期子目录存储；uploads/ 不入 git |
| 多轮上下文超限 | 只取最近 10 轮拼接，超出截断（不做 token 精确计算，qwen-plus 131k 上下文余量充足） |
| LangChain 生态版本 | langchain-core / langchain-openai / langchain-community / langgraph 版本需对齐，requirements.txt 锁定版本号，升级时整体升 |
| MinerU 解析耗时 | 本地 CPU 每页数秒：解析走后台任务（BackgroundTasks），status=processing → ready/failed，前端轮询；无 GPU 或量大可切官方 API（MINERU_MODE=api） |
